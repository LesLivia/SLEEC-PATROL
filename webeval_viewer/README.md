# webeval_viewer: the answers of the SLEEC-PATROL diagnosis evaluation

The manager's read-only view of what participants answered on the study site
(`webeval/`), modelled on UI_static_viewer (ITS repo). It is a second Cloudflare Pages
site connected to the same R2 bucket. It only reads that bucket; nothing in it can write
or delete.

- **Login:** a username and password, checked by `functions/api/login.js`. On success it
  sets a signed session cookie, valid for 8 hours (HttpOnly, Secure, SameSite=Strict).
- **List:** one row per participant's file: session id, expertise, the environments
  submitted, the number of answers, and when they last submitted.
- **Detail:** one submission. A picker steps through its answers. Each answer is shown
  beside the rule page it is about, as the participant saw it: the rule in plain words,
  the rule panel and its Diagnosis buttons. The participant's answer is shown read-only.

Only `/api/*` (the answers) is behind the login (`functions/_middleware.js`). The page
files and the study data in `public/` are public, like the study site itself.

## Layout

```
webeval_viewer/
  public/                     what Pages serves
    index.html, app.js        login, list, detail
    styles.css                webeval's styles.css, plus the viewer's own section at the end
    report.css                COPY of webeval/public/report.css
    data/                     GENERATED by scripts/build_data.py - do not edit
  functions/_middleware.js    the login gate on /api/*         (as UI_static_viewer)
  functions/api/login.js      POST: check the login, set the cookie  (as UI_static_viewer)
  functions/api/logout.js     POST: clear the cookie           (as UI_static_viewer)
  functions/api/submissions.js  GET: list the summaries        (as UI_static_viewer,
                                 environments read from `env`)
  functions/api/submission.js GET ?id=: one participant's file (as UI_static_viewer)
  scripts/build_data.py       webeval/scripts/build_data.py, writing into this folder
  wrangler.toml               the Pages project and the bucket binding (no secrets)
```

## The data

Each answer is shown against `public/data`, so this has to be the same data the study
site serves. Build it from the same prerun answers and content as the study, whenever the
study's data is built. Run it in WSL, in the webapp's env, from the repo root:

```
python webeval_viewer/scripts/build_data.py
```

## The manager's login: three secrets, never in a file

The functions read `ADMIN_USERNAME`, `ADMIN_PASSWORD` and `SESSION_SECRET`.
`SESSION_SECRET` is a long random string that signs the login cookie. Generate one with:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Changing `SESSION_SECRET` logs everyone out.

**On Cloudflare:** store them as encrypted secrets of the viewer project. Each command asks
for the value:

```
wrangler pages secret put ADMIN_USERNAME --project-name sleec-patrol-eval-viewer
wrangler pages secret put ADMIN_PASSWORD --project-name sleec-patrol-eval-viewer
wrangler pages secret put SESSION_SECRET --project-name sleec-patrol-eval-viewer
```

You can also add them in the dashboard: Workers & Pages → `sleec-patrol-eval-viewer` →
Settings → Variables and Secrets, with type *Secret*. They apply to deployments made after
they are set, so set them before the first deploy, or deploy again afterwards.

**Locally:** put the same three lines in `webeval_viewer/.dev.vars`, which `wrangler pages
dev` reads:

```
ADMIN_USERNAME=...
ADMIN_PASSWORD=...
SESSION_SECRET=...
```

`.dev.vars` is in `.gitignore`. Never put the login in `wrangler.toml`, in the code, or in
git.

## Testing locally

```
cd webeval_viewer
wrangler pages dev
```

Open http://localhost:8788. `wrangler.toml` binds the bucket with `remote = true`, so a
local run reads the **real** answers. That is safe, because the viewer never writes. To use
a simulated bucket instead, remove that line.

## Deploying

The first time, from `webeval_viewer/`:

```
wrangler pages project create sleec-patrol-eval-viewer --production-branch main
```

Then set the three secrets as above. Every deploy, from `webeval_viewer/`:

```
wrangler pages deploy --branch main --commit-dirty=true
```

The viewer's address is `sleec-patrol-eval-viewer.pages.dev`.
