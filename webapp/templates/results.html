Reading the report

Defeater responses

A rule may carry exceptions, written with unless. Before anything is verified, each rule is normalized into alternatives that have no exceptions left — one for the main case, one for every exception that states a response of its own. A rule written as:

r when A then B unless C then D

becomes two alternatives, which are what actually gets checked:

r_main      when A and (not C)   then B
r_unless1   when A and C         then D

So the main case no longer applies where the exception does, and the exception carries its own obligation. A rule written without unless stays a single alternative under its own name, and an unless with no then only withdraws the obligation, so it adds nothing to check. Defeater responses above counts these alternatives — the checks Marabou actually ran.

Every other figure above counts rules as written, not alternatives: a rule is compliant only if all of its alternatives are, and one violated alternative makes the whole rule violated. So a rule is counted once, however many alternatives it was split into.

Unverified cases

Every alternative is handed to Marabou as one question: does an input exist that satisfies the condition yet breaks the response? Marabou answers sat — such an input exists, so the rule is violated and the input is shown as a counter-example — or unsat: no such input exists, so the rule holds over the whole declared range.

Anything else is an unverified case: the search ended without an answer, typically on a timeout, a resource limit or a solver error. The rule is then neither proved nor disproved — an unverified case is not a violation, and not a clean result either.

The verdicts

  • COMPLIANT the model complies with the rule: nothing in the declared ranges breaks it.
  • VIOLATED the model can break the rule, and the counter-example that breaks it is shown.
  • UNVERIFIED the Marabou verification did not finish for some reason (e.g. a timeout, a memory limit), so the rule is left open: neither proved nor broken.
