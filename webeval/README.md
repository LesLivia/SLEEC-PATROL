# webeval: SLEEC-PATROL diagnosis evaluation

A static site for the user study, modelled on UI_static (ITS repo): Cloudflare Pages
serves the pages, and one Pages Function stores the answers in R2.

A participant gives their expertise, reads the instructions, then goes through the two
environments in a fixed order, Highway then SDD-OIA. Each environment starts with an intro
page (background and pictures). Then each **violated** rule has its own page: the rule's
panel and diagnosis as the webapp's results page shows them, beside a form asking:

1. Does the diagnosis help you to understand the violation? (yes / no)
2. If no, what could be clearer? (required on no)

Each environment is submitted when its last rule is answered.

## Layout

```
webeval/
  public/                     what Pages serves
    index.html, app.js        the pages and their logic
    styles.css                the site's own styles
    report.css                COPY of the <style> block of webapp/templates/results.html
    data/                     GENERATED by scripts/build_data.py - do not edit
    images/                   the instructions' example diagnosis (a screenshot, see below)
  functions/api/submit.js     POST /api/submit -> R2
  templates/rule.html         COPY of the one-rule pieces of webapp/templates/results.html
  content/<setup>/            hand-written: background.txt, note.txt, pictures.json,
                              rules.json (each rule in plain words, shown above its
                              panel), and for Highway the recorded scene.json
  scripts/build_data.py       builds public/data from the prerun answers
  scripts/capture_highway_scene.py   records the Highway intro observation (run once)
  wrangler.toml               the Pages project and its R2 binding
```

`report.css` and `templates/rule.html` are copies, so the site stays separate from the
webapp. When the webapp's report changes, copy the change into them by hand.

## Building the data

Run from the repo root in WSL, in the webapp's env:

```
python webeval/scripts/build_data.py
```

For each environment, the script:

- reads `webapp/examples/<setup>/prerun.json` **as it is**, without checking that it still
  matches the spec
- builds the report with `webapp.core`
- writes one page per violated rule, plus the backgrounds, the pictures and
  `manifest.json`.

It prints which rules it built and when each prerun was solved. After a change to a
spec, a model or the parser:

1. Rerun `python -m webapp.prerun`.
2. Rerun this script.
3. Deploy again.

The Highway intro picture is drawn by `webapp/scenes/highway.py` from
`content/highway-fast-v0/scene.json`, one real highway-fast-v0 observation. That file was
recorded once with `python webeval/scripts/capture_highway_scene.py`, run with the
Windows Python, which has highway-env. The script sets the seed and the number of
steps. The SDD-OIA pictures are copied from
`autonomous_driving/CBM/rss/data/mini_boia_out` (git-ignored). Their captions are read
from each image's scene file.

The example diagnosis on the instructions page, `public/images/diagnosis_example.png`, is
a screenshot of Highway rule r8's main-part diagnosis from the built site. It has numbered
marks that match the list above it. It was taken on 2026-10-23, and the build does not
regenerate it, so re-take it if the Highway results change.

## Testing locally

```
cd webeval
wrangler pages dev
```

Open http://localhost:8788. `wrangler.toml` binds the bucket with `remote = true`, so
answers from a local run go to the **real** bucket `sleec-patrol-eval-submissions`. The
binding table wrangler prints at start-up shows that bucket's mode as `remote`. Delete
test files from the bucket afterwards. To test without touching it, remove the
`remote = true` line. Answers then go to a simulated bucket under `webeval/.wrangler/state`
(git-ignored).

## Deploying

The first time, create the project. Its name, `sleec-patrol-eval` in `wrangler.toml`,
becomes the address `sleec-patrol-eval.pages.dev`. If that name is taken on pages.dev,
Cloudflare adds a suffix.

```
cd webeval
wrangler pages project create sleec-patrol-eval --production-branch main
```

Every deploy, from `webeval/`:

```
wrangler pages deploy --branch main
```

Pass `--branch main`. Without it, wrangler uses the current git branch, and a deploy from
any branch other than the production one becomes a preview deployment, not the live
site.

## Reading the answers

There is one file per participant, `submissions/<sessionId>.json`, in the R2 bucket. List
the files in the Cloudflare dashboard (R2 → the bucket). To fetch one:

```
wrangler r2 object get sleec-patrol-eval-submissions/submissions/<sessionId>.json --remote --file <sessionId>.json
```

```json
{
  "sessionId": "…", "expertise": "…",
  "started_at": "…", "first_submitted_at": "…", "last_submitted_at": "…",
  "submissions": [
    { "submitted_at": "…", "env": "highway-fast-v0",
      "evaluations": [ { "env": "highway-fast-v0", "rule": "r8",
                         "form": { "helps": "no", "clearer": "…" } } ] },
    { "submitted_at": "…", "env": "sddoia", "evaluations": [ … ] }
  ]
}
```

How sessions work:

- A participant gets their id on their first submit, at the end of Highway. The SDD-OIA
  submit goes into the same file.
- Submitting an environment again replaces its earlier answers.
- The id lives in the browser tab. Closing the tab, or "Start over", starts a new
  file.
